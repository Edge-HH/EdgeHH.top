## 三种任务

| 模式 | 做什么 |
| --- | --- |
| 复制并校验 | 复制完成后，用所选算法重新读取源文件和目标文件并比对摘要 |
| 仅复制 | 只复制，不计算摘要 |
| 只校验 | 不复制，只校验目标目录里已有的对应文件 |

创建任务时至少要启用复制或校验中的一项。只校验适合拷完以后隔一段时间再确认一遍，或者校验别人拷好的盘。

## 安全复制

- 保留完整的目录结构，包括空目录；尽量保留源文件的最后修改时间，保留不了时记一条警告，不中断任务。
- 默认顺序异步复制，以 4 MiB 缓冲区流式读写，大文件也不会整个载入内存。
- 先写入随机命名的 `.clipport-partial` 临时文件，完整写入后再改成正式文件名。取消或单个文件失败时清理临时文件，不会用半个文件覆盖已有的目标文件。
- 开始前检查目标磁盘空间，拒绝源目录和目标目录互相包含之类的危险组合。
- 跳过目录联接和符号链接，阻止目标路径穿过重解析点，避免意外递归或写到别的地方。
- 单个文件出现读写、权限或校验错误时，任务会继续处理其他文件。
- 后台流式扫描源目录，扫描时界面不卡，并实时显示已发现的目录数、文件数、数据量和当前路径（main 分支）。

## 校验算法

| 算法 | 特点 | 建议用途 |
| --- | --- | --- |
| SHA-256 | 速度与安全余量均衡，256 位摘要 | 默认选择；重要素材交付、长期归档 |
| SHA-512 | 512 位摘要，计算开销通常更高 | 对长期保存要求更高的归档 |
| SHA-1 | 160 位摘要，便于兼容旧清单 | 只用于必须兼容 SHA-1 的旧流程 |
| MD5 | 开销低、兼容性高，已不具备可靠的抗碰撞能力 | 旧系统、旧清单 |
| xxHash64 | 吞吐量优先，非密码学算法 | 本机大批量的快速完整性检查 |

- 所选算法贯穿普通任务、只校验、失败重试、覆盖后重新校验、历史记录和报告，报告里写明实际使用的算法和源、目标两边的摘要。
- 摘要用来发现复制错误或文件变化，不等于数字签名。没有特殊需要时保留默认的 SHA-256。
- 拷贝时校验（main 分支，默认关闭）：用一个低 I/O 优先级的后台线程，校验已经完整写入的文件，复制始终优先；后台忙不过来时，剩下的文件在复制结束后继续校验。

## 重复文件与出错处理

- 目标位置已有同名文件时，可以选：询问、覆盖、跳过、创建副本。选“询问”时先处理其他文件，最后再逐个或批量决定，支持多选和全选。
- 任务结束前可以勾选失败的文件选择重试或跳过；摘要不一致的文件可以覆盖后重新校验。
- 失败、取消或意外中断的任务可以按原配置重新开始；已完成复制的任务可以再启动一次只校验，沿用原来的算法。

## 队列与优先任务

- 可以创建多个任务排队执行，同一时刻只有一个任务真正读写磁盘，避免并发拷贝导致速度骤降或崩溃。
- 会阻止同时运行的任务使用相互冲突的源路径或目标路径。
- 勾选“优先执行”的任务排到队列最前面。main 分支进一步改为：当前普通任务先在安全检查点停稳，再把执行权交给优先任务，优先任务暂停或完成后原任务自动继续。
- 每个任务都能单独暂停、继续、取消；可以选择在任务期间阻止电脑休眠。

## 进度与吞吐图

- 显示当前阶段、当前文件、完成百分比、文件数量、数据量、速度和实际耗时。main 分支中，扫描阶段改为显示不定总量的进度，不会把还没扫完的任务报成 100%。
- 复制和校验分别记录字节速度和文件数速度，绘制实时波形，标出当前值、最高值和最低值，刻度随数据自动调整。复制图和校验图可以并排，也可以上下堆叠。
- 吞吐采样随任务历史保存，之后点开历史任务仍能看到当时的图表。

## 历史与报告

- 任务历史以 JSON 保存在本机，最多保留 200 条已结束的记录；正在运行的任务不会因为达到上限而被删除。某条记录损坏时只隔离这一条。
- 可以删除单条或批量删除已结束的记录，删除记录不会删除源文件和目标文件。
- 导出单个报告，或者为多个任务批量生成报告。报告语言跟随界面语言，包含任务模式、校验算法、摘要、失败、警告和重复文件的处理明细。

## 通知（main 分支）

- “设置 → 通知”里可以同时添加多个企业微信、钉钉、飞书、Bark 或 SMTP 邮件渠道，同类型也能加多个，每个渠道都有“测试推送”。
- 可以分别选择“任务完成”和“任务失败”时通知；主动取消默认不发失败通知。通知在结果、历史和报告保存之后才发送，发送失败只记日志，不影响任务结果。
- Webhook 地址里的 Token 和 SMTP 密码使用 Windows DPAPI 按当前用户加密保存。

## 文件资源管理器右键菜单

- 右击文件夹或文件夹空白处，选“新建 ClipPort 任务 → 作为源目录 / 作为目标目录”，ClipPort 会打开并预填新任务。已经在运行时，请求会交给现有窗口。
- 在“设置 → 快速开启”中启用。传统右键菜单直接注册到当前用户，不需要管理员权限或证书，Windows 10 也能用；Windows 11 首层的新式右键菜单由单独的稀疏 MSIX 组件提供，需要 Windows 11 22000 以上，测试版签名需要手动信任证书。
- 启用右键菜单后不要移动或拆分程序目录。

## 外观、语言与更新

- 浅色、深色或跟随系统；主题色可以用 Windows 强调色，或海沫绿、亮玫红、黄金色、浅薄荷色、紫影色五种预设。
- 界面语言：简体中文、English 和文言，切换后可以立即安全重启。日志和报告的保存目录可以修改。
- “设置 → 关于 → 检查更新”从 GitHub Releases 获取新版本（包括预发布版），下载后校验 SHA-256 再重启替换；设置、任务历史、日志和报告不受影响。

## fnOS 版（开发中）

app/fnos 分支正在开发飞牛 fnOS 原生版：自包含的 Linux x64 应用，不使用 Docker，也不需要在设备上另装 .NET 或 Node.js，界面用 React 编写，和 Windows 版共用同一套 .NET 复制与校验核心。它通过 fnOS 的统一网关提供页面，不额外开放端口，使用 fnOS 原生的共享目录选择器，右键菜单对应为“授权目录”管理。目前还没有发布安装包。

## 安装与系统要求

- Windows 10 1809 或更高版本，x64。
- 在 [Releases](https://github.com/Edge-HH/ClipPort/releases) 下载 `ClipPort-1.0.0-beta-win-x64.zip`（附 SHA-256 校验文件），解压后运行 `ClipPort.exe`。发布包是自包含的目录，不是单文件程序，也不是 MSIX 安装包。
- 数据位置：设置和任务历史在 `%LOCALAPPDATA%\ClipPort`，日志和自动报告默认在“文档\ClipPort”。

## 使用步骤

1. 点击“创建任务”，或者在文件资源管理器的右键菜单里预填目录。
2. 选择源目录或存储卡；需要复制时再选择目标目录，可以额外填一个目标子文件夹名。
3. 选择任务模式、校验算法、重复文件处理方式，以及是否防止休眠、是否优先执行。
4. 点击“开始任务”，在主界面查看进度和吞吐图。
5. 出现重复文件或失败文件时，按提示逐个或批量处理。
6. 结束后导出报告、重新开始，或者再启动一次只校验。
